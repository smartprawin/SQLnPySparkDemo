#features of s3 : simple storage service


#1) scalable storage
#2) it can store structured, semi strucutred and unstructured data
#3) Durability: 99.99999999% durable
#4) data is highly protected.
#5) it stores copies of your data across different regions to make sure its available and to avoid redundancy.
#6) security:
#Encryption: your data will tranformed to something that humans cant read or understand. we need a key to decrpt this data and only the person with the right persmission will have the key.
#access control: IAM (identity access management) : we can monitor who can access , what can they access and we can restrict to file level. Bucket policies.
#7) data lifecycle management: we can set up lifecycle policies to automatically transition data from one type of storage to another.
#8) even notifications: s3 can send notification for when ever you create an object or delete an object or change an object. (SNS -simple notificaion service)
#9) Cross-region replication (CRR): s3 can replicate objects across different regions which mean when one site goes down another can start working like nothing happened. Disaster recovery
#10) logging and monitoring: when you enable logging and monitoring for s3  - cloudwatch. every click or every move or every action in the bucket recorded and if something goes this is where we can check what went wronga nd why ?


#s3 classes:


#1) s3 standard: when we need data all the time. or very often access: frequently access data, cost is higher.
#retrieval time : alwaysa available


#2) s3 Intelligent Tiering: automatically move data between 2 types of buckets frequent and infrequent depending on patterns.
#retrieval time is milliseconds
#moving data between standard and infrequent access it is cheaper and cost optimised.


#3) s3 glacier: used for archival data and we might need the data from mins to hours.
# retrieval time is 1-12 hours
# cost is very low compared to standard


#4) s3 glacier deep archive: data is rarely accessed.
#retrieval time: 12 hours
#cost : very low.


#5) s3 one zone Infrequent access: infrequent access that is store only in one zone.
#same Intelligent tiering
#acces:  milliseconds
#low storage costs cmpared to standard.

#EMR Achitecture


#master node:(team leader) it the leader node, he keeps track of progress, makes sure everyting is running smoothly
#if the master node fails the entire project fails. Schedules, he monitors and assigns tasks


#Core nodes: (team members): they store parts of data , they process that data by running tasks. if cored node fails then we might loose some data.


#task nodes:(support workers) these are optional nodes which only support core node to process the data but they dont store the data.
#u can add them when you need extra processing power. if the task node fails , no data is lost.




#storage options:


#HDFS : hadoop distributed file system: this is like storing files across multiple team members. its fast but its temporary,
#whn the cluster finishes running or shutsdown the data disappears.

#EMRFS: EMRfile system: this is like native memory, it is faster to read and write to s3 or it will make it easier.

import json
import boto3


glue_client = boto3.client('glue')


def lambda_handler(event, context):
  crawler_name = 'landingbucket-crawler'
  # TODO implement
  print('event received: ', json.dumps(event))


  try:
    response = glue_client.start_crawler(Name=crawler_name)
    print('Crawler started successfully')
    return {
      'statusCode': 200,
      'body': json.dumps('Hello from Lambda!')
    }
  except glue_client.exceptions.CrawlerRunningException:
    print('Crawler is already running')
    return {
      'statusCode': 200,
      'body': json.dumps('Crawler is already running')
    }
  except Exception as e:
    print('Error starting crawler: ', str(e))
    return {
      'statusCode': 500,
      'body': json.dumps('Error starting crawler')
    }

def binarysearch(arr, target):
 low = 0
 high = len(arr) - 1


 while low<=high:
  mid = (low+high)//2
  if arr[mid] == target:
   return True
  elif arr[mid] < target:
   low = mid + 1
  else:
   high = mid - 1
 return False


#each step cuts search space in half steps


#time complexity O(log n) (very efficient)
